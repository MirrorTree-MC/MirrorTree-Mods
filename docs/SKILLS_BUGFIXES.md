# MirrorSkills 三项行为修复

日期：2026-10-23。基线：`44ed137`。修改 LIStorm 与 Journey 的源码，不部署正式客户端或服务器，不改动生产玩家进度。

## 药水标记和隐藏效果

- 原版 `MobEffectInstance.update` 原位替换数值；原实现只在复制构造时传递标记。现在在实际写入 duration/amplifier 后分别采用传入效果对应的标记，包括 false。只延长同等级时长时，保留原有等级标记；拒绝的低等级效果不覆盖当前标记。
- 在 `setDetailsFrom` 后复制两项标记，覆盖复制构造和隐藏效果晋升。注入时机位于原版保存旧效果之后，避免旧效果的标记被新效果污染。
- 原版隐藏层使用 `Details` 编解码，绕开外层 codec。现在递归读写每层原有的两个 `mirrorskills.*Modified` 字段；缺失字段继续按 false 读取，不更换存储格式或标记名。
- 技能调整重建效果时保留隐藏链。Journey 在服务器线程直接把完整效果编码为独立 JSON 快照，避免原版浅复制构造丢弃隐藏链；快照仍在传送前保存。

## 无限时长

`isInfiniteDuration()` 为 true 时跳过时长乘法，保留原版 `-1` 哨兵。等级调整照常执行，有限时长的计算公式保持。负面时长减免 100% 也不把无限效果变为 0；时长缩放不等同于免疫。

## 死亡闪回

记录中的维度非法、为空或未加载，以及坐标不是有限数时，返回失败并保留记录。只有旧记录缺失维度字段（null）才延续使用当前世界的兼容行为。

检查原版 `teleportTo` 的返回值。返回 false 时反馈失败，成功后才复制当前技能附件、清除死亡位置并发布；不提前修改共享附件。中英文提示均已补齐。

## 兼容与验证边界

技能、参数、命令、附件、网络、药水标记和技能树节点 ID 均保持，技能树来源 JSON 字节不变。未增加依赖或 CI。

旧存档里已经丢失的标记，无法可靠区分“未加成”与“加成后丢失”，因此本次不会猜测或回写历史药水数值；修复阻止后续再次丢失。

Journey 的 JSON 效果保存/恢复格式通过共同 codec 的回归场景验证。完整卧室床交互与生产模组组合未在本次重新验收；Journey 破坏性验证探针仅编译，不运行。

## 回归证据

新增 `SkillsRegressionGameTest` 的六个场景：

1. 同类药水刷新后复制、NBT 保存恢复和重新添加；分别验证时长与等级标记的采用、清除与保留。
2. 三层隐藏效果经 JSON/NBT 往返与逐层晋升；验证技能调整、显示标记及快照恢复仍保留隐藏链。
3. 正面/负面无限效果在 0%、50%、100% 负面时长减免下保持无限，等级可调整；有限效果仍使用原公式。
4. 缺失、非法、空维度及 NaN 坐标失败时保留记录；旧 null 维度记录仍可在当前世界成功使用一次。
5. 原版因玩家 removed 状态返回 false 时保留完整死亡记录。
6. 真正致死伤害触发死亡事件，经原版客户端重生请求和附件 copyOnDeath，在主世界重生后闪回下界；成功后不可再次使用。嵌入式玩家完成原版加载握手，避免维度切换保护影响伤害测试。

修复前的生产字节码运行新增测试，五个缺陷场景失败，原有三个服务端测试通过；另一个真实死亡场景的测试准备随后按原版握手/重生入口补齐。修复后九个服务端 GameTest 全部通过，包含真实死亡到跨维度闪回完整链路。`checkSkillData` 的 codec、复制隔离与旧死亡记录检查通过。
