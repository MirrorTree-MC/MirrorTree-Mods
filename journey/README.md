# MirrorTree Journey · 26.1.2

客户端物品/装饰器与梦境逻辑合为一个 Fabric 模组，mod ID 为 `mirrortree`，两端安装同一个 JAR。需要 LIStorm 和 Starry Skies，完整依赖见[安装说明](../docs/INSTALLATION.md)。

- 客户端窗口标题显示 `MirrorTree · AnotherAutumn | 26.1.2-Fabric | Ciallo～(∠・ω< )⌒★`；周目标识随客户端模组版本更新，Minecraft 版本自动读取，进入或退出世界后标题保持一致。
- 新玩家从服务器配置的卧室出生。生存模式玩家通过任意传送进入卧室时切为冒险模式，从卧室传送到其他维度时恢复生存模式；商店传送、命令传送和床入梦均适用。卧室内传送保持冒险模式，创造和旁观模式保持不变；管理员可用创造模式建造。
- 卧室保留普通玩家的建筑保护，同时允许右键各模组商店、玩偶机和玩偶，并允许放置、破坏 Numismatic Overhaul 的生存商店；在受保护方块上放置商店时需要潜行，普通右键不会打开原本受保护的容器。客户端与服务端均需更新到同一版 MirrorTree JAR。
- 右键卧室的床入梦；首次打开选择菜单，可选择「随机入梦」或「加入聚落」。随机入梦仍在主世界半径 3000 内寻找安全落点；候选高度不得明显超过该列生成地形的高度，避免落在高空飞船、浮岛或屋顶上，不设置统一的高山限高；加入聚落会在选定 warp 附近寻找安全位置。两者均登记 LIStorm 入梦点和个人重生点。
- 在主世界成功躺床后，点击聊天栏「回到卧室」执行 `/wakeup`；再次使用卧室的床返回保存的位置和状态。通过其他跨维度传送离开卧室时，也会恢复暂存状态并结算本次梦境，位置仍由该传送决定。记录校验或预先保存失败时取消传送，保留状态供修复后重试。卧室死亡重生会作废暂存状态，后续入梦不会恢复死亡前的生命、饥饿或效果。
- `/wakeup` 仅允许正在主世界睡觉的玩家使用；`/redream` 需要管理员权限。全局出生点不随入梦改变。

快照保存在当前世界的 `mirrortree/dreams/<UUID>.json`，包含位置、生命、饥饿、饱和度、消耗度和完整效果。保留旧 `config/mirrortree/dream_data.json` 坐标记录读取，且不删除旧文件。新记录增加可选的 `returning` 标记，用于在返回提交中断后、下次卧室传送前恢复记录状态；旧记录仍可直接读取。新快照也记录死亡次数，防止死亡后作废写入失败、重启再读取时复用过期状态。更新不重置现有玩家、技能或物品，也不导入卧室建筑。

## 聚落管理

聚落功能使用服务端 Essential Commands 0.39.0-mc26.1.1 或兼容新版的 warp 数据；无需复制或手动修改 `world_data.dat`。没有安装时仍可随机入梦。聚落菜单沿用原来的识别规则：位于 `minecraft:overworld`，名称以中文全角冒号的 `聚落：` 开头，并且玩家具有对应 warp 的访问权限。普通 `shop`、卧室中的 warp 和英文冒号 `聚落:` 都不会列入聚落。列表支持分页。

- 管理员站在主世界的目标位置执行 `/mtwarp 名称`，会保存 `聚落：名称` warp 和朝向，并创建聚落入梦点灯笼。需要 2 级管理权限；同名聚落不会被覆盖。名称包含空格时使用双引号。
- `/mtwarp-delete 名称` 删除对应聚落和已加载的同名灯笼；此版本创建的未加载灯笼会在以后加载时清理。普通商店 warp 不受影响。
- 已保存梦境返回记录的玩家仍直接返回原位置和状态。首次选择菜单会核对床的位置，离开床边或变为旁观者后不能通过旧菜单入梦；传送等待期间也会再次检查 warp、权限和世界边界。失效或不安全的聚落不会偷偷改为随机传送。

菜单使用原版箱子界面协议，按钮物品不能拿走，玩家背包和光标物品不会被菜单操作改变。客户端和服务端仍安装同一个 Journey JAR；服务端更新在重启后生效。

开发和隔离验证规则见 [AGENTS.md](AGENTS.md)，许可见 [LICENSE](LICENSE)。
